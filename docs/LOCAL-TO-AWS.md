# Local testing and AWS promotion

The integration runtime is `src/sre/server.mjs`. It runs the same normalization, store, worker, analytic schema, and rollback policy locally and in a Linux container. Configuration chooses SQLite/Postgres, offline rules/Claude/legacy Eve, vendor readers, and Teams transport. The old port-3000 auction lab and SQS adapter remain teaching fixtures. For an Ally implementation, start with the [developer handoff](ALLY-HANDOFF.md) and [integration checklist](ALLY-INTEGRATION-CHECKLIST.md).

## Profiles

1. **Offline:** `pnpm sre:dev`, then open port 3001 or use `pnpm sre:seed`. Try all four scenarios, questions, an unauthorized simulated approver, and explicit approval. Rollback dispatch is visibly simulated and never changes the pilot. No vendor or model calls occur.
2. **Local PostgreSQL:** optionally run `docker compose up -d postgres`, then `DATABASE_URL=postgresql://sre:sre-local-only@127.0.0.1:5432/sre pnpm sre:dev`. Compose binds the database to loopback and persists a named volume. Its password is exclusively for local development. Docker was unavailable here. A separately built local PostgreSQL 17.11 server passed the [fifteen-case network/process exercise](POSTGRES-EXERCISE.md); PGlite remains part of the fast SQL regression suite.
3. **Teams protocol:** `SRE_TEAMS_MODE=playground pnpm sre:dev` with no CLIENT_ID/CLIENT_SECRET/TENANT_ID. Point Agents Playground to port 3978 and match synthetic tenant/conversation IDs in a local config. Never expose this unauthenticated mode through a tunnel.
4. **Connected local:** copy the connected example, scope it to dedicated test resources, configure secrets, and enable one connector at a time. Start with `SRE_AGENT_MODE=rules`. `pnpm sre:check --live` performs reads only. Live Teams uses authenticated input through an HTTPS tunnel. Connected rollback can dispatch a real workflow only if explicitly configured, eligible, and approved.
5. **Claude model evaluation:** install an approved Claude Code CLI and configure unattended model authentication, then select `SRE_AGENT_MODE=claude` in the scoped connected profile. The host sends a bounded evidence snapshot to `claude -p`; no Eve service or OpenAI credentials are required. The supplied container needs the CLI added through approved packaging. See [Claude runtime](CLAUDE-RUNTIME.md). The optional legacy Eve profile still requires `SRE_AGENT_MODE=eve`, `EVE_URL`, `EVE_TOKEN`, and its separately running agent. Real model/query use can incur charges.
6. **Measured recovery drill:** `pnpm sre:drill bid-race` uses the existing generated auction commits with mocked vendor transports and real signed local HTTP ingress. It exercises the connected dispatch code against a GitHub protocol fixture, then restarts the database-backed service and verifies the exact target artifact plus health/invariants. `pnpm sre:exercise 21` repeats all seven scenarios three times with retained reports/databases. These are bounded local contract exercises, not a multi-hour uptime or live tenant test. Use `pnpm sre:ready --json` to inventory missing credentials without contacting vendors.

## Verification and promotion gates

`node --test tests/*.test.mjs` exercises domain defects, scoped connectors, inbox/outbox, worker lease/fencing, restart persistence, incident isolation, correlated source closure, thresholds, webhooks, actual Teams SDK local round trips, live-auth rejection, both dispatch request contracts, approval/replay/expiry/revocation, stale releases, and ambiguous writes. Teams collaboration tests simulate two responders, passive updates, a direct instruction, thread isolation, restart into the same model session, and a telemetry flood. A fake Eve client verifies what context is delivered without making a paid model call. ICD 203 tests cover required fields, unsupported likelihood terms/citations, abstention, PR stage transitions, commit binding, and assessment history. `pnpm agent:build` compiles the optional agent and skill without calling a model.

Before AWS:

- Test real sandbox repositories/projects, Jira, ServiceNow CI, Dynatrace entity, and a dedicated Teams conversation. Prove permissions, source schemas, token expiry, pagination, proactive threads, uninstall/reinstall, and restart. Build the Teams install ZIP with `pnpm sre:teams:package`; test both mentions and RSC-enabled responder updates using the flow in INTEGRATIONS.md. Mock successes do not establish tenant access.
- Install a protected rollback workflow against a disposable deployment. Prove it rejects changed runtime SHA, unknown artifact, unsafe migration, repeated request ID, wrong environment, and expired authorization. Exercise GitHub and GitLab independently, including actual deployment and health callbacks.
- Evaluate the model on held-out changes/incidents with stale CI, truncated diffs, contradictory sources, copied alerts, missing data, dependency faults, and hostile source text. Measure evidence grounding, abstention, false positives/negatives, unsafe recommendations, latency, and cost. Record forecasts before outcomes. Assess calibration only with enough representative outcomes; ICD terminology alone is not calibrated prediction.
- The bounded local PostgreSQL exercise covers separate processes, lease expiry during real lock waits, connection termination during writes, retry races, application-clock offsets, immediate-shutdown/WAL recovery and agent SIGKILL. A separate [logical backup/restore drill](BACKUP-RESTORE.md) covers restoration into a new cluster and quarantining lost-interval external effects. Still validate production TLS/IAM, physical/PITR backups, replica failover, selected-infrastructure restoration, multi-host timing and real Teams delivery uncertainty. Local TCP tests do not establish RDS behavior.

## AWS target

If AWS is the approved target, start with one ECS service/task, managed Postgres, Secrets Manager and TLS ingress. Build the provided Dockerfile on Linux for the target architecture, adding the approved Claude CLI and unattended provider authentication for the Claude profile. Mount a real connected config and configure DATABASE_URL with verified TLS. Incident/model context is reconstructed from the application database; ephemeral task storage is insufficient for durable state. A legacy Eve deployment separately needs its authenticated runtime and supported persistent session backend. The Dockerfile is not an applied infrastructure stack, and the approved Ally hosting target still needs confirmation.

Only authenticated webhook and Teams activity routes need external ingress. Restrict the operator API/UI to the operations network; its bearer token grants access across configured services. Claude receives its incident snapshot on stdin; the legacy Eve path uses a separate five-minute, one-incident evidence capability. Keep read and rollback write identities separate. Route `/api/messages` to port 3978 and vendor webhook routes to port 3001. Never expose the original port-3000 lab.

Database jobs are the queue for this version. SQS/Step Functions are not required for local parity. If later added, preserve the transactional inbox, event identity, lease fencing, and outbox semantics.

Before production, provision and test backups/restore, retention, schema migration operations, TLS/secret rotation, IAM, readiness checks, and alarms for stale polling, dead jobs, stuck leases, failed/unknown notifications, unknown dispatches, database growth, and model/query budgets. No AWS provisioning, tenant smoke test, production model evaluation, or cloud recovery has been performed here.

## Delivery uncertainty

The [Agent health report](AGENT-OPERATIONS.md) exposes stale polling, dead/delayed work, loop progress, delivery uncertainty, and unverified dispatches through the console and authenticated `/api/operations`. `pnpm sre:health --strict` reads it for an external supervisor. Scoped Teams operational notices are transactional and quiet while unchanged. Keep an independent external alarm because the agent's own sender can fail with the agent.

Reads retry within bounded budgets. Investigation jobs retry three times then become dead. Expired worker leases can be reclaimed. Repeated event identities are deduplicated; pending telemetry jobs are coalesced while operator questions are retained. Stable conclusions suppress repeated notifications.

An external message/workflow can be accepted while its response is lost. Such actions become unknown and are not blindly retried. Reconcile the saved request ID with the external workflow/thread before retrying. Dispatched means submission, not recovery. Resolution requires all correlated problem sources closed and fresh independent health verification matching the exact recorded deployment identity, timestamp, SHA, and artifact, with technical and business checks. A matching rollbackRequestId in the trusted release and verification records reconciles a dispatched/unknown rollback to verified; a successful workflow alone does not.
