# Ally connector and service checklist

Use this as the integration inventory, not as a claim that Ally access exists. All Ally endpoints, resource identifiers, identities, policies, and acceptance results are **unknown until provided and verified**. Record sensitive completed values/evidence in an approved private system. Commit only sanitized contracts, configuration examples, code, and tests.

The intended first pilot described in this project uses ServiceNow MCP, GitLab, Dynatrace, Teams, Claude, and a durable service/database. Confirm that selection with the owners. GitHub/Jira and direct ServiceNow REST are supported alternatives or supplements, not automatic requirements.

## Writes and recovery: separate, optional work

| Capability | What exists | Missing enterprise integration / proof |
| --- | --- | --- |
| Release metadata publisher | Signed `/webhooks/releases/<service-key>` intake and deployment ledger | Trusted pipeline must publish actual SHA, immutable artifact, native deployment identity/time, environment, compatibility and measured checks. Configure `releases.webhookSecretEnv`. Synthetic fixture attestations are not usable production evidence. |
| Independent recovery verifier | Signed `/webhooks/verification/<service-key>`; exact deployment and freshness checks | Independent technical and business-invariant checker, its signing identity/secret and real proof payload. Configure `verification.webhookSecretEnv`/`maxAgeSeconds`. Source closure and fresh matching proof are required; model text and CI success cannot replace them. |
| Rollback pipeline | Host policy, explicit Teams approver/room checks, proposal/nonce/expiry, durable dispatch and GitHub/GitLab dispatch clients | Deployment owner must implement the protected pipeline, serialize environment actions, deduplicate request IDs, verify exact current/target artifacts and compatibility, recheck queued approval expiry and publish outcomes. Separate `rollback.tokenEnv`/OAuth write identity. Keep disabled until authorized sandbox acceptance. [Dispatch contract](INTEGRATIONS.md#rollback-workflow-contract), [no-change/uncertain outcomes](WORKFLOW-APPROVAL.md) |
| Generic code fix / QA executor | Plan/approval/audit records and `qaAdapter` extension; `fixtures/qa-sandbox.mjs` for trusted local auction code | A reviewed isolated worker, pinned approved source, dependency/build policy, bounded execution, cancellation, artifact provenance and safe result collection. The current adapter contract is local-only. Do not connect an arbitrary remote executor or run untrusted code with service credentials. |
| External ticket updates / MR publication / merges | Immutable Markdown plans, local fixture branches/patches/MR drafts, read-only change tracking | No live ServiceNow/Jira ticket writer, remote fix-branch/MR publisher or merge capability is supplied. Add only specific authorized actions with independent identity/audit and failure handling. A tracked MR can be read without granting publication rights. |

For inbound provider hooks, configure separate `webhookSecretEnv` values and the exact authentication/payload contracts in [INTEGRATIONS.md](INTEGRATIONS.md#webhooks-and-read-access). Outbound polling authorization and inbound webhook authorization are separate. ServiceNow/Dynatrace active reconciliation can supply incident intake without assuming a workflow already exists; repository review/CI hooks and custom releases/health publishers need their own wiring.

## Acceptance record to complete in Ally

For each selected integration, record the approved owner, scope, auth mode, sanitized contract/version, test resource, observation date, result, evidence reference, and unresolved limits. Do not record credentials. A checklist row is accepted only for its tested scope.

- [ ] Clean clone installs from the lockfile and the existing offline suite passes; environment and results recorded.
- [ ] Required services, resource IDs, identity routes, data handling, and network access confirmed by owners.
- [ ] Private connected config passes `pnpm sre:ready --strict --json`; all enabled placeholders replaced.
- [ ] Each enabled reader passes its real operation-specific `pnpm sre:check --live --json` probes. Disabled/unverified operations remain explicit.
- [ ] A real scoped incident survives restart, with recent and old-active intake, complete pagination, source closure, denied/expired permissions and correct tenant/environment isolation tested.
- [ ] Actual Ally Teams identities and installation pass shared-incident, separate-incident and lifecycle/delivery tests.
- [ ] Approved Claude route passes bounded real-evidence investigations and representative quality/cost evaluation.
- [ ] Ownership importer, expiry/shift behavior and contact uncertainty verified.
- [ ] Selected database/host, backups/restore/cutover, TLS, secrets/rotation, retention and independent monitoring accepted.
- [ ] If execution is requested: protected pipeline plus signed release/health publishers pass sandbox safety, expiry, idempotency, uncertain-result and business-invariant checks before enabling the writer.

There is no completed Ally acceptance record in this repository. Earlier personal/trial-tenant results and local fixture counts are useful development evidence, not substitutes for this record.
