# Ally connector and service checklist

Use this as the integration inventory, not as a claim that Ally access exists. All Ally endpoints, resource identifiers, identities, policies, and acceptance results are **unknown until provided and verified**. Record sensitive completed values/evidence in an approved private system. Commit only sanitized contracts, configuration examples, code, and tests.

The current production slice is **continuous Dynatrace log ingestion and active diagnostic queries, bounded GitLab source discovery, evidence-linked code findings, and outbound Teams webhook delivery**. Service/repository/revision mapping is initially unknown and must be investigated inside an approved discovery boundary. That boundary and its owner are not yet known. ServiceNow, Jira, Confluence, native Teams conversations/requests, broader collaboration, and source-system create/update capabilities remain [future goals](JIRA-TICKETS.md#ticket-02-future-integrations-and-actions).

The canonical [Jira ticket packet](JIRA-TICKETS.md) contains both complete ticket bodies, Claude ticketing instructions, and the review/open decisions. [Ticket 01](JIRA-TICKETS.md#ticket-01-dynatrace-logs-and-gitlab-code-findings) retains production AWS VM hosting, `claude -p` console streaming, and storage **TBD**. Polling supports discovery/reconciliation; logs drive diagnosis. Local reference/requirement checks and static source review do not establish live or production acceptance. The inventory below includes future capabilities whose acceptance does not gate the current ticket.
