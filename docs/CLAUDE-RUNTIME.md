# Ally Claude runtime

The normal `pnpm sre:dev` command and connected example select `agentMode: "claude"`. The development command uses a separate unseeded profile on port 3010; `pnpm sre:lab` explicitly retains the offline rules fixtures. See [Claude development](CLAUDE-AGENT-DEVELOPMENT.md). The service runs each investigation or Teams follow-up through **`claude -p`**. It does not require OpenAI credentials, an OpenAI model endpoint, or the legacy Eve service. The interactive demo (`pnpm sre:trial:demo`, port 3002) currently defaults to offline rules for the requested coordination tests. Select `SRE_TRIAL_DEMO_AGENT_MODE=claude` explicitly for a real `claude -p` trial with fictional connector evidence and simulated Teams/rollback actions. Local fixture mode remains offline `rules`.

The persistent Node service owns polling, ServiceNow/Dynatrace/GitHub adapters, the incident database, Teams conversations, worker leases and approval checks. It gathers a bounded incident snapshot and sends it to Claude on stdin. Incident content is not placed in process arguments. Claude streams user-facing text through bounded NDJSON and returns a final structured investigation/risk object with source findings, an issue spec and selected Teams-message requests; the service independently checks evidence and deployment references before publishing an assessment. Model text cannot approve, execute or verify a rollback.

## Setup

Install an Ally-approved Claude Code CLI on the service host and authenticate that service account through the approved Claude/enterprise provider route. The command flags were exercised with Claude Code **2.1.299**. Check the selected enterprise build before deployment; unsupported flags fail rather than selecting another model provider. Model authentication and permissions are separate from the vendor reader credentials.

```sh
claude --version
# Copy/configure the connected example and vendor settings first.
SRE_CONFIG=.local/sre.connected.json SRE_AGENT_MODE=claude pnpm sre:dev
```

Optional `SRE_CLAUDE_BIN` selects an executable path (no shell command or extra arguments). `SRE_CLAUDE_MODEL` selects a Claude model/deployment alias; omit it to use the approved CLI default. Do not copy an OpenAI model ID into this setting.

The profile's `claude` object supports `command`, `model`, `effort` (default `medium`), `timeoutMs` (100–300000, default 180000), `bare` (default false) and optional positive `maxBudgetUsd`. `SRE_CLAUDE_EFFORT` overrides effort with `low`, `medium`, `high`, `xhigh` or `max`; the installed CLI/model must support the selected value. The Claude worker limit is the configured CLI timeout plus 60 seconds for collection and persistence (four minutes by default). Responses are prompted to stay concise. No extra paid fallback or automatic command replay is configured. A recognized account usage-limit response pauses the model queue across incidents and preserves the exact pending question batch without consuming its ordinary failure budget. The console displays the provider reset label when available. A label without a date is guidance, not an absolute retry deadline. After checking account availability, an authenticated local/API operator uses Resume investigations with a reason; the durable hold and its release remain in the audit. See [quota recovery](SUSTAINED-GROUP-EVALUATION.md#provider-quota-holds). Other transient investigation failures retain the existing bounded retries.

Default CLI mode retains the CLI's login authentication. Restricted mode excludes user/project settings; supply provider configuration through the forwarded environment, managed enterprise settings, or an approved executable wrapper. Managed policies still apply. The service forwards Claude/Anthropic and AWS/Azure provider environment variables plus selected OS, proxy, certificate and Google credentials settings. It excludes SRE, database, Teams, repository-writer, OpenAI credentials and Node startup injection settings. The running environment object's changed Claude credentials apply to the next turn; editing a file alone does not reload a running process.

For an API/Bedrock/Vertex/Foundry deployment, `claude.bare:true` additionally disables customization discovery. Bare mode **does not use subscription OAuth/keychain credentials**; it needs the corresponding approved provider credentials. Do not enable it merely to reuse an interactive subscription login. [Anthropic's headless guide](https://code.claude.com/docs/en/headless) documents this authentication difference.

The existing Node-only container image does not install Claude Code or carry enterprise login credentials. Use an approved image/host containing the CLI and the required service-account authentication before deploying this profile.

## Context and process handling

Each invocation uses a private temporary working directory, restricted mode, disabled built-in tools/skills/hooks, an empty explicit MCP configuration, denied MCP tools, no permission prompts, and JSON schema output. These investigations use evidence collected by the service's REST adapters or its host-owned read-only ServiceNow MCP adapter. The latter has been tested against mocks; it does not give the Claude subprocess direct MCP execution. No Dynatrace MCP server is configured. [CLI flags and managed-setting behavior](https://code.claude.com/docs/en/cli-reference) remain subject to the installed enterprise version.

The incident/session identity, responder reports and assessment history stay in the application database. Each turn receives its current bounded snapshot. CLI transcript persistence/resume is disabled, so recovery does not depend on a machine-local Claude transcript or an older Eve session. A crash may require a fresh read-only model invocation and additional inference cost. Successful analysis publication still requires the current worker lease and incident revision; the model does not receive recovery authority.

Stdout is limited to 1 MiB, stderr to 64 KiB, and both streamed UTF-8/NDJSON and the terminal result envelope must validate. Only main-turn text deltas and a fixed analysis-stage marker enter bounded session progress; init metadata, tools and thinking blocks are excluded. Progress is provisional and is not sent to Teams. Checkpoint writes are throttled to one per second. The completed structured result is separately validated and fenced. Nonzero exit, error envelopes, malformed output, foreign evidence and timeouts fail the job with controlled diagnostics. Raw CLI stdout/stderr are not included in job errors. Cancellation/timeout terminates the owned process group on macOS/Linux, escalating to SIGKILL if needed, before removing the temporary directory. Windows process-tree cleanup has not been validated.
Code comparisons use separate selection lanes for provider, comparison type, available project/repository and review number before the 240-candidate and 80-evidence limits. The model window and digest take one witness from each family before older heads of a busy review. These lanes preserve visibility; they do not verify provider scope, the latest head, completeness, cause or deployment. Existing authority checks remain separate. A missing/incomplete current read stays unknown. Family counts in the model coverage describe its supplied snapshot, with omitted families explicit; they are not an inventory of the whole database or provider.

The comparison transport budget remains 24,000 bytes inside the 160,000-byte total. Budget classification uses the original evidence identity, because clipping can remove `comparisonKind` from a large body's displayed excerpt. Clipped comparisons cannot consume the telemetry allowance instead. The raw SQL record and original timestamp remain retained; omitted/clipped content is unavailable to the model. Local rules/mocks verify these bounds while actual Claude stays off; this is not a model-quality acceptance result.

Stdout is limited to 1 MiB, stderr to 64 KiB, and both stdout UTF-8 and the result envelope must validate. Nonzero exit, error envelopes, malformed output, foreign evidence and timeouts fail the job with controlled diagnostics. Raw CLI stdout/stderr are not included in job errors. Cancellation/timeout terminates the owned process group on macOS/Linux, escalating to SIGKILL if needed, before removing the temporary directory. Windows process-tree cleanup has not been validated.

Claude's summary has a schema limit of 600 Unicode characters and an independent host-side check rejecting blank or oversized summaries. The prompt requests three short sentences; sentence count and factual quality are not established by the length check. Detailed reasoning remains in the other structured fields and the expandable assessment. Rules and legacy Eve retain their existing summary contract.

The restart test closes the service and reopens SQLite; supervisor SIGKILL during an active Claude call remains a pending process-ownership drill. An additional retained local drill ran the actual installed Claude CLI against a loopback Anthropic protocol fixture and observed the `StructuredOutput` tool and validated result. That proves CLI/protocol wiring with synthetic data; it does not establish live Claude authentication, Ally network policy, reasoning quality, vendor access, or Teams installation/delivery. `sre:ready` reports CLI availability/authentication as unverified and makes no model call.

The later multi-group coordination checkpoint uses no actual Claude inference. Its host-side briefings and explicit reported-state disagreement checks passed with offline rules. ## Current development contract

Claude output must include source findings (possibly empty), a remediation object, a draft issue specification, and selected Teams messages (possibly empty). Missing remediation fails both the generation contract and the host output-shape check. File/SHA/line and evidence references are checked against the delivered snapshot. The model cannot cite unseen evidence or select a foreign/unjoined room. The host rechecks current audience membership while committing selected messages. General source collection and durable question batching apply to Claude; the fixture-only policy catalog remains an explicit offline testing path. See [development and evaluation](CLAUDE-AGENT-DEVELOPMENT.md) for exact bounds and verification scope.

`candidateSha` attributes introduction to a deployment change; it is separate from an immutable faulty-code location. A non-null candidate requires `changeAssessment:"likely"` and an eligible deployment. Unknown/unlikely change attribution with a non-null candidate is rejected, not rewritten. A pre-existing defect can still name its current file/SHA in `codeFindings` and support a forward fix without blaming the latest deployment. The prompt rechecks this distinction on follow-ups.

`model-citations.mjs` gives Claude and the explicit local Codex evaluator shorter citation references scoped to the exact bounded snapshot. Both the input and generation schema use those references. The host restores typed citations and prose references to the original durable IDs before source, scope, recovery and output-length validation or persistence. Unknown, raw, other-snapshot and foreign references fail. Source bytes, file paths/SHAs and room identities retain their original values. Citation aliases do not grant access or change which records were delivered. Shared batch-wide triage coverage/interpretation is sent once in `logTriageBatches`; each selected row retains its actual samples/stratum and a resolvable reference. Missing shared context stays unknown. Both representations remain within the 160 KB snapshot cap.

Top-level `investigationConcurrency` is an integer from one to eight, default one. The development profile explicitly uses four. Capacity is database-wide, and each incident remains exclusive. Stop investigators before changing it; idle capacity changes fence older configurations. A free slot can serve quieter incidents while another model is slow. A recognized account cap blocks new claims across all slots; already admitted calls may finish, and repeated cap responses retain one exact hold ID. Greater concurrency increases simultaneous CLI, memory and provider usage and needs acceptance on the approved route.

The host suppresses repeated proactive model messages using the material assessment and durable per-room queued-text fingerprints. The model can select at most four custom messages. Every requesting room in a published batch and every retained required-thread destination still gets one reply: the host uses the full assessment for destinations without custom wording, preserving source findings, remediation and the issue specification. Audience authorization and incident binding are rechecked inside the publication transaction; a revoked destination rolls the transaction back. An empty selection remains silent for proactive work, while direct requests retain their reply obligations. Queuing is distinct from external delivery and acknowledgement; restore retains the fingerprints and account holds.

New Claude batches admit at most 32 same-incident questions and 32 KiB of serialized UTF-8 request data, with the existing 4,000-character limit per question. The incident snapshot retains its independent 160 KB bound. Questions that cannot fit remain pending in full, rather than being truncated or marked answered. Both CLI adapters validate these bounds before native startup. Saved pre-upgrade eight-question batches retain their original characters and full payload; an explicit host-owned legacy version permits their earlier size up to 192 KiB including worst-case JSON escaping. New batches record version 2 and never use that exception. Stop older investigator binaries before upgrading; incident/room permissions and exclusive leases do not change.

Generation and host validation reject high confidence when the candidate, byte, metadata or deployment window omitted evidence, the signal digest reports limited coverage, or retained source rows are incomplete/synthetic. The host receives the actual bounded snapshot coverage, so bypassing the generation schema cannot bypass this check. An absence of omission flags does not prove health or causality. Tick stall monitoring allows the full worker budget plus ten seconds (250 seconds at the default Claude timeout), preserving a larger configured threshold. Other operational lanes retain their own limits.

The CLI uses `stream-json` with completed text-block progress, omitting optional token-level partial envelopes. The parser still accepts fragmented/partial streams without repeating completed text, and excludes thinking, tool inputs, initialization data and subagent output. This follows the documented [block/message stream](https://code.claude.com/docs/en/agent-sdk/streaming-output) and reduces transport overhead without raising the 1 MiB stdout limit. Completed invocation metadata records byte/event counts, elapsed/first-text timing, input hash/size, bounded numeric token/turn/API-duration fields and StructuredOutput attempt/error counts. It retains no raw thinking, tool arguments or diagnostic contents. [StructuredOutput validation retries](https://code.claude.com/docs/en/agent-sdk/structured-outputs#recognize-the-structuredoutput-tool-call) are distinguished from additional worker invocations. The prompt targets roughly 450 words, one progress sentence and a single structured report, with explicit nested object boundaries. It separates the purpose of each section and reserves custom room messages for distinct coordination needs; direct-request fallbacks retain the full assessment. Required sections, source locations, controls, coverage and recovery blockers remain required; this is guidance, not a token or latency guarantee. The default-model replay and explicit model/capacity workload remain separate observations.

For the explicitly requested Sonnet route used in the concurrent development evaluation, run `SRE_CLAUDE_MODEL=sonnet SRE_CLAUDE_EFFORT=medium pnpm sre:groups:eval --live --concurrency 4`. The same environment settings can select that route for `pnpm sre:dev`. Choose the approved model/deployment alias for a connected environment; an alias is a requested route, not a separately attested server-side model identity or latency guarantee.

The host now applies a bounded settling gate after stale direct/required-reply investigations: five seconds of quiet accepted intake, at most sixty seconds per stale turn. A request may recover its earlier fair position once; subsequent stale retries retain normal last-served scheduling. SQL preserves the exact request, gate and scheduling metadata through restart/restore, while external-action holds and current-revision publication fences remain unchanged. The model cannot request priority or choose these deadlines. Historical version-4–7 concurrent evaluations and legacy serial evaluators retain their earlier admission policy; fresh version-8 evaluations pin the new policy.
Deployment transport also reserves witnesses by native identity before repeated-delivery counts. Current stored success, incident-start releases, eligible historical health observations and unsettled versions precede ordinary recent history in the existing 20-record/26,000-byte deployment allowance. The 160,000-byte total is unchanged. Projected coverage reports incomplete identities, retained SHA/artifact or status conflicts, omitted tied current identities and ambiguous local simulation scope. Roles and health flags describe retained source claims; they cannot authorize recovery or certify live provider state. The host uses the same bounded ledger independently in recovery/no-change verification. These changes were exercised with rules and mocks while actual Claude remained off.

The deployment projection now includes bounded `attestationConflicts` entries naming a field and its source conflict time. Conflicting raw values remain in retained evidence; the collapsed deployment withholds the disputed field. A later status without that field cannot reconcile it. JSON type and missing/null distinctions survive SQL selection. Conflict descriptors are host-derived selection metadata, not model/provider authority. Current and target policy, independent recovery and no-change verification block unresolved attestations even if model prose is unchanged or optimistic.

The signal digest projects a bounded `incidentScope` descriptor and per-group `scopeRelation`. A reported descriptor comes from the host log-monitor issue/hash contract; its time describes that source observation. Ordinary native problems without this contract remain scope-unverified. Different scopes may still be related through dependencies; unknown or contradictory aliases cannot exclude a competing failure. Scope labels do not authorize actions or merge incidents. A scope source ID omitted from final model evidence is removed and marked `evidenceOmitted`; the 160,000-byte total and existing digest/entry limits are unchanged.
Log sample reservations now run before the source candidate cap and preserve typed/conflicting record metadata and partial/sampling receipts when selecting raw model evidence. Request/trace IDs normalize only explicit correlation values in message strings; other message numbers remain significant. This changes which bounded source rows survive repetition pressure. It does not enlarge model budgets, authorize tools, supply omitted history or establish actual Claude diagnostic quality. Claude remains off in the local acceptance drills.
